# T1Bridge v1 security review

Status: pre-release review record, 2026-09-05. This review applies to the
current private tree and the boundaries defined in
[`architecture.md`](../architecture.md). It records source and synthetic-test
evidence, including offline package-lifecycle fixtures and the current
single-machine hardware record. It does not claim that signed or hosted
packaging or any release gate has passed.

This review covers shipped T1Bridge packages and public interfaces. Omarchy's
installer, automatic onboarding, and desktop UI policy have separate downstream
acceptance. Shipped importers and standard authentication/password fallback are
still release requirements.

Hardware evidence is from core/DKMS/libfprint/fprintd revisions 58/7/5/1 or
earlier recorded cohorts. The newer UVC and libfprint parser changes have
synthetic evidence only; they have not been installed for hardware acceptance.

Suspend is tested only where the host already supports safe suspend; an
unavailable path is recorded as not run and is non-blocking. Kernel upstream
submission and review are separate, non-blocking follow-up. Neither exception
waives the required two-machine hardware matrix.

## Threat model

The protected assets are the authentication result, transient ACM credentials,
biometric and catacomb material, the xART anti-replay record, privileged input
and display access, and kernel integrity. Inputs from the T1 device, persisted
files, local IPC peers, and the unprivileged Touch Bar process are untrusted
until validated. Diagnostics must not disclose opaque payloads,
credentials, identifiers, or filesystem-derived secrets.

The standing rule from project Decision 10 is applied directly: a privileged
component or listening socket remains in v1 only where the following table
states its hardware or authentication purpose. Missing live enforcement is an
open release blocker, not evidence that a boundary is safe.

The reviewed architecture defines four listeners: the T1-facing xART listener,
the direct authentication socket, the root-only standard fingerprint socket,
and the local Touch Bar hardware socket. The two authentication sockets feed
one broker, scheduler, and hardware worker rather than separate privileged
services. All four have bounded production adapters and packaged service
policy. This source and
offline package evidence does not replace live activation, peer-admission,
failure, teardown, or hardware evidence for any listener.

Rust `unsafe` remains confined to five dedicated, private FFI modules:
`t1-platform::ffi`, the daemon NSS-account, service-lifecycle, and xART-listener
adapters, and the Touch Bar cancellation adapter. Each wraps an in-tree C
boundary whose safe Rust owner lives in the same crate. No protocol, storage,
authorization, renderer, or desktop-provider module permits unsafe code. This
is the implemented multi-crate form of Decision 19's focused audited-boundary
requirement; consolidating those unrelated boundaries into one crate would
increase coupling without reducing the native surface.

## Concrete negative-test map

The patched libfprint suite passes 132/132; fprintd passes 560/560 against that
build on a private mock system bus with virtual readers and `pam_wrapper`.
Native and software duplicate-check fixtures separately cover stage counts,
preservation, cleanup success, and cleanup failure. All PAM and Polkit
authorization cases passed. These are synthetic results, not live
password-fallback evidence. The compatibility watch runs both suites.

| Risk | Evidence and invariant |
| --- | --- |
| Malformed or oversized device/protocol input | [`framing.rs`](../../crates/t1-bridge/src/framing.rs) rejects bad magic, unsupported versions, trailing frames, and oversized bodies before allocation. [`mesa.rs`](../../crates/t1-bridge/src/mesa.rs) rejects truncation, length mismatches, invalid users, and invalid completion identifiers. SEP relay, ACM, and keystore tests reject wrong endpoints, selectors, tokens, versions, seals, declared lengths, and exhausted transactions. |
| Confused deputy or forged local result | Authentication tests reject non-local and unauthorized peers, permit only one active operation, restrict cancellation, and accept only the exact success response. The socket adapter admits only the exact systemd listener path, obtains credentials from the kernel, denies unauthorized credentials before reading a request, loads the recorded owner at admission, binds completion to the originating session/token, and treats confirmed disconnect or probe failure as cancellation. Owner-store failure permits only exact root cancellation of existing work. The live event loop remains a service obligation. |
| Mutation before validation or after failure | [`user_workflow.rs`](../../crates/t1-bridge/src/user_workflow.rs) validates all identities before rebind mutation and stops after each failed command. [`catacomb_restore.rs`](../../crates/t1-daemons/src/catacomb_restore.rs) validates stored state and master/user ordering before later mutation. Enrollment reserves paired storage before the first sensor command, uses only an approved keybag state, commits user then master, revalidates the committed identity, releases ACM before SEP, and attempts relay restart on success, failure, cancellation, timeout, or unwind. Enrollment and match workflows always attempt cancellation after a possibly started operation and do not convert timeout or malformed completion into success ([enrollment](../../crates/t1-bridge/src/enroll_workflow.rs), [matching](../../crates/t1-bridge/src/match_workflow.rs)). |
| Persistence races, traversal, and unsafe metadata | xART tests reject symlinks, wrong owner/mode, empty and oversized data; atomic replacement preserves a complete record. Catacomb tests reject mixed or partial generations, unsafe links/modes/owners, out-of-order writes, and failed promotion without replacing the prior active pair. Import coordination rejects unsafe destination/orphan state, preserves a renamed destination when final durability is uncertain, and requires revalidation on the next run. |
| Secret or identifier disclosure | Sensitive fields use redacted `Debug`, and covered storage and workflow errors avoid opaque payload bytes. Enrollment tests explicitly cover `Display`, `Debug`, error-source traversal, and post-commit revalidation errors. SEP diagnostics are status-only, and secret-bearing SEP, XZ, PBZX, selected-FDR, and catacomb buffers have explicit clear or wipe paths. |
| Native memory safety regressions | Root [`Makefile`](../../Makefile) rebuilds the socket, NCM, preserved-ESP/import, Touch Bar C boundary, PAM, and eight SEP suites into isolated GCC AddressSanitizer/UndefinedBehaviorSanitizer outputs with leak detection, separate from normal incremental builds. |
| Camera descriptor memory/buffer safety | The H.264 parser rejects short and inconsistent descriptors, invalid interval tables, zero dimensions, and frame-size overflow in normal and sanitized tests. |
| Malformed libfprint broker input | The driver rejects bad framing, versions, reserved bytes, lengths, UTF-8, identity bounds, zero identifiers, invalid fingers, duplicates, truncation, and trailing bytes. The parser passes ASan/UBSan and the full patched libfprint suite passes 132/132. |
| iBridge lifecycle confusion or cross-device mutation | [`t1_ncm_ready.c`](../../crates/t1-daemons/c/t1_ncm_ready.c) mutates only the independently discovered expected interface index and revalidates identity. Synthetic rejection plus exact-package autosuspend, cycle, live-loss, recovery, camera, Touch Bar, and SEP checks pass on the active machine. |
| Root target-user assertion and Polkit bypass | The standard socket admits only UID 0, resolves the asserted username at call time, binds it to the enrolled owner, and rejects unprivileged cross-user requests before claiming a token or mutating state. The libfprint driver is root-only; ordinary enrollment authorization remains fprintd's Polkit boundary. |
| Desktop-provider command injection, reordering, or denial of service | [`desktop_provider.rs`](../../crates/t1-touchbar/src/desktop_provider.rs) accepts one absolute executable and fixed argv without a shell. Status and values are versioned and bounded; calls have a 500 ms deadline off the render loop. One bounded FIFO preserves discrete action order and coalesces only consecutive volume updates. Process fixtures cover actions, ordering, malformed/oversized output, nonzero exit, timeout, missing capability, and disappearance while core controls remain independent. |

## Findings and fixes

| Finding | Resolution | Evidence |
| --- | --- | --- |
| Release tag verification accepted any valid signature in the temporary keyring, even from an unrelated public key accompanying the approved subkey. | **Fixed.** In addition to matching the build's commit/tag objects, the signing job requires exactly one valid signature bound to the configured primary fingerprint. | The exact workflow shell accepts the expected signing subkey and rejects an unrelated signer, an unsigned tag, a changed tag object, and a changed commit using disposable GPG fixtures. This is not project-key custody or signed-release acceptance. |
| Enrollment transport and event errors were redacted when formatted but could still expose caller-owned details through the standard error source chain. | **Fixed.** Opaque transport/event variants no longer return their inner error as a source; structural command and Mesa errors remain inspectable. | `EnrollmentError::source` and `errors_events_and_outcomes_are_redaction_safe` in [`enroll_workflow.rs`](../../crates/t1-bridge/src/enroll_workflow.rs). |
| The dependency-free SEP C suites lacked one repeatable memory-safety execution gate in the canonical quality path. | **Fixed.** An isolated GCC ASan/UBSan/leak run now rebuilds and executes all eight suites through `make quality`. | Root and SEP [`Makefile`](../../sep-probe/Makefile) targets; sanitizer and normal suites pass in the current private tree. |
| A crash could leave one exact active-marker temporary that blocked later live-validated catacomb recovery. | **Fixed.** Recovery validates and removes only its own stale temporary before recreating it, and also converges when the active marker was already replaced. | Recovery crash-point tests in [`catacomb_store.rs`](../../crates/t1-daemons/src/catacomb_store.rs). |
| An unprivileged user could pre-create the shared SEP lock on hosts where `/run/lock` is mode `1777`, causing biometric denial of service. | **Mitigated.** The userspace package's tmpfiles entry creates or corrects the mandated lock as root-owned mode `0600`; the DKMS package does not own it. Before the first package install without a boot-time tmpfiles run, a squat may persist, but native validation fails closed and password authentication remains available. | [`t1bridge.conf`](../../systemd/t1bridge.conf) and lock-identity tests in [`test_sep_operation.c`](../../sep-probe/test_sep_operation.c). |
| Deadline selection lacked an exact service-level delivery method and could be integrated without preserving the active slot. | **Fixed.** The service routes the exact scheduled operation through the existing cancellation authority; delivery is idempotent and cannot release or replace the worker before exact completion. | Scheduler identity, cancellation, and slot-retention tests in [`auth_scheduler.rs`](../../crates/t1-daemons/src/auth_scheduler.rs). |
| Accepted IPv6 sockets may report scope zero even when the listener is bound to the dynamically discovered T1 interface. | **Fixed in policy; live evidence pending.** The adapter contract requires a kernel-bound listener. Admission accepts zero or the matching scope, rejects every wrong nonzero scope and wrong listener index, and retains exact link-local peer matching. | Peer-admission tests in [`xart_service.rs`](../../crates/t1-daemons/src/xart_service.rs); live protocol-constant verification remains pending in [`hardware-validation.md`](../hardware-validation.md). |
| Cancellation state could be split between broker policy and a delivery slot, allowing an acknowledgement or later match to observe different authorities. | **Fixed.** `BrokerState` is the sole token/cancellation authority; the slot only delivers the exact token event. `OKAY` is returned only after delivery, disconnect uses the same path, cancellation beats later match, and stale completion cannot finish newer work. | [`auth_protocol.rs`](../../crates/t1-daemons/src/auth_protocol.rs), [`auth_session.rs`](../../crates/t1-daemons/src/auth_session.rs), and their cancellation-race tests. |
| A disconnect probe based only on readable data could miss peer closure while one packet remained queued, permitting work to continue for a dead client. | **Fixed.** The native non-consuming probe checks hangup independently of readability and reports closure even with queued data; the connection-bound coordinator then delivers exact-token cancellation. | `test_disconnect_probe_is_non_consuming_and_fail_closed` in [`test_t1_seqpacket.c`](../../crates/t1-daemons/c/test_t1_seqpacket.c) and [`auth_socket.rs`](../../crates/t1-daemons/src/auth_socket.rs). |
| Best-effort recovery could replace the primary catacomb finish/promotion failure, obscuring the operation that actually failed. | **Fixed.** Preservation remains best effort when a primary error already exists; mandatory relay restart still has the explicitly approved overriding precedence, including unwind paths. | Recovery-precedence tests in [`catacomb_session.rs`](../../crates/t1-daemons/src/catacomb_session.rs), [`catacomb_store.rs`](../../crates/t1-daemons/src/catacomb_store.rs), and [`enrollment_lifecycle.rs`](../../crates/t1-daemons/src/enrollment_lifecycle.rs). |
| A master export or durable master write failure after the user export had been durably written and finished in SEP could drop the only matching user export. | **Fixed.** Both master-stage failure paths now attempt to preserve the durable user export as a pending recovery artifact while returning the primary failure. | `failure_after_user_finish_preserves_its_durable_export` in [`catacomb_session.rs`](../../crates/t1-daemons/src/catacomb_session.rs). |
| The SEP keystore/session C boundary accepted a request pointer and trusted the operation descriptor's length without receiving the caller's actual buffer length. | **Fixed.** Both layers now require an explicit request-buffer length and reject a mismatch before hashing, copying, or transport I/O. | Short-buffer rejection tests in [`test_sep_keystore.c`](../../sep-probe/test_sep_keystore.c) and [`test_sep_session.c`](../../sep-probe/test_sep_session.c). |
| An ACM builder could partially populate the session output buffer and then fail locally without clearing the retained transfer bytes. | **Fixed.** Local builder argument and state failures clear the session transfer buffers before returning. | `test_acm_builder_failure_clears_partial_transfer` in [`test_sep_session.c`](../../sep-probe/test_sep_session.c). |
| Moving a recovery stage only after SEP export could lose the sole recoverable generation if the rename failed. | **Fixed.** Enrollment durably reserves and renames the generation before the first native save; later pre-marker promotion failure retains the complete generation and blocks replacement until recovery resolves it. | `reserve_recovery`, `promote_after_native_finish`, and `finalized_pair_is_retained_when_pre_marker_promotion_fails` in [`catacomb_store.rs`](../../crates/t1-daemons/src/catacomb_store.rs). |
| Rejecting a duplicate selected FDR object cleared the rejected candidate but could leave the first selected object in memory on the error path. | **Fixed.** Selection owns a drop-time wipe, while the duplicate candidate is wiped before rejection; successful extraction transfers ownership without clearing the result. | `Selection::store`, `Selection::drop`, and wipe tests in [`walk.rs`](../../crates/t1-import/src/walk.rs). |
| Per-chunk PBZX limits allowed multiple raw or XZ chunks, including nested streams, to exceed the intended total expansion budget. | **Fixed.** One checked aggregate expansion counter is shared across the entire walk, charged before allocation or decoding, and rejects overflow without changing accounted usage. | Aggregate, pre-allocation, and overflow tests in [`walk.rs`](../../crates/t1-import/src/walk.rs). |

## Review conclusion

The active machine has exact-package evidence for cold boot, fingerprint,
PAM, Touch Bar, camera, and composite-device recovery. This is not a v1
security approval. Automatic ESP import, cross-machine xART admission,
broker-down Polkit/lock fallback, signed hosted installation, the second
machine, and the complete release gate remain pending. Publication is not
authorized by this record.
